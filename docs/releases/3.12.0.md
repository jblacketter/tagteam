# 3.12.0: Role-neutral readiness and onboarding

Codex and Claude can each lead or review using the same workflow. Watcher
completion and start messages use plain text so Codex does not reject Claude
plugin slash commands. Plan approval explicitly requests implementation.

- Readiness uses the packaged canonical contract, independent of Claude's plugin.
- New instruction pointers are created only when absent. Reusable templates read
  current roles from tagteam.yaml; historical cycles retain their participants.
- Status/priming shows the configured roles and launch commands. Tmux pane titles
  use configured names; missing roles no longer select default providers.
- Active participant mismatches refuse ordinary cycle writes and automated
  dispatch, including direct headless and lead-conversation paths.

Finish active work before changing roles. Stop/recreate the watcher and agent
sessions after editing configuration. Restore the recorded assignment to recover
from an accidental mid-cycle switch; human rulings and read/status remain usable.
Existing terminal panes are not automatically identified, stopped or replaced.
Unconfigured direct Python cycle callers retain their explicit-name API; actual
agent launch still requires configured roles. A pre-existing SQLite WAL index
may be refreshed by a read-only check, as documented in Phase 50; cycle history
and database contents are unchanged by a refusal.

This release does not make customized legacy upgrades safe. Wait for Phase 52's
migration preview/preservation work before downstream cleanup. No tool credentials,
private memories, or project-specific policies are migrated. Release publication
uses scripts/release.py and the existing post-merge process.
