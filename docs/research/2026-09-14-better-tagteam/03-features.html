1. Since-you-left digest

Problem

You start the agents, walk away, and come back hours later. The cockpit shows state, not change. The CLI has tagteam state and cycle rounds --tail, which also show state.

Idea

tagteam digest [--since 9h] and a card at the top of the cockpit: every round since your last visit with its verdict word, gates that bounced, phases closed, escalations waiting, tokens and window state. Deterministic first (it is a query over tables that exist). Optional second step: a Haiku one-paragraph narrative ("Codex approved search-index on round 2 after one gate bounce for two failing tests…").

Evidence it is needed

Your own pattern in this request: "I'll review in the morning". The 2026-08-16 cockpit issue is the same complaint in a different form.

Proof it worked

Cold-open the cockpit after a headless run; say what happened within ten seconds without scrolling.

Principle

Visibility of system status. Recognition over recall.

2. Phase cost report

Problem

When a phase closes, nothing records what it took. tagteam usage --phase exists but nobody runs it, and Codex turns are unpriced.

Idea

On impl approval, append one block to docs/phases/<phase>.md and the decision log: rounds, bounces, lead/reviewer/gate time, tokens by role and model, API-equivalent cost, wall clock start to approve. Add a Codex price table so the estimate is not blank. Show the same block in the cockpit when the Start card appears for the next phase.

Evidence

The usage table has the columns; 0 of 25 Codex rows are priced; the roadmap's status lines already hand-record "gate 1,789 passed" but nothing about cost.

Proof

Every closed phase has the block; the numbers feed the bench (#3) and the Health tab (#12). Also portfolio evidence for the showcase.

3. Review bench: your handoff history is an eval set

Problem

"Should the reviewer run on Sonnet?" cannot be answered without a labeled set, and the standard advice is to build one. You already have one: every round in docs/handoffs/*.jsonl across every project, with the reviewer's verdict and, for escalations, your ruling.

Idea

tagteam bench review --phase X --round N --cell opus:medium --cell sonnet:high: check out the round's commit in a scratch worktree, rebuild the reviewer packet exactly as the orchestrator did, run each cell with the panel contract (writes verdict.json, never the cycle), and tabulate verdict agreement, blockers found, tokens, seconds. Extend to lenses and to the briefer.

Evidence

Anthropic's guidance: sweep effort before model, price the tail, never swap a model without an eval. tagteam panel preview already rebuilds the exact prompt without spawning, so half the plumbing exists.

Proof

A table for 20 historical rounds that shows which cells found the same blockers. That table decides #4 and #5.

Caveat

Reviewer turns read the repo; the worktree must be at the checked commit, and the test command must be safe to run there. Both are already solved by the roadmap-worktree code.

4. Model policy by activity kind

Described in Agents & models, step 3. A models: table in tagteam.yaml keyed by kind (lead.plan, reviewer.review, panel.scope, briefer, summaries), every entry optional, merged into the role's validated args at spawn. tagteam state prints the resolved policy. Small change because argv is already built per kind.

5. Subagent kit in the plugin

Described in Agents & models, step 4: test-runner (Haiku, read-only), explore, codex-brief (Sonnet), verifier (no write tools). Shipped under plugin/agents/ so every project gets them from the plugin, respecting the backlog's condition (read-only mode shipped in 3.11). First experiment needs no agent files at all: set CLAUDE_CODE_SUBAGENT_MODEL=haiku in the headless child's environment and compare a long impl turn's modelUsage before and after.

6. Grade the review

Problem

You read every review. Your opinion of it ("caught a real bug" / "nitpick" / "missed the obvious") evaporates. That opinion is the only ground truth for review quality.

Idea

One click on any verdict card in the reviewer lane, or tagteam grade --round N good|nit|miss "note". Stored beside the round. Shown in the Health tab per model and effort. Feeds the bench as labels.

Evidence

Anthropic's guidance on advisor/orchestrator shapes says the fragile variable is whether the cheap model's judgment holds; without labels you cannot tell. Cheapest possible labeling: the arbiter is already reading.

Proof

After 30 grades, a table: grade by model × effort. If it is flat, tier down. If it is not, you know exactly where.

7. Lead self-review pre-flight

Before SUBMIT_FOR_REVIEW, the lead runs the scope and verification lenses on Sonnet against its own diff (the lens briefs exist; panel preview can render them for the lead) and fixes what they flag. The gate already does this for tests; this does it for "did you do what the plan said" and "did you prove it". Measure rounds per phase (#2) before and after; if it does not reduce rounds, delete it.

8. PR on impl approval

You already work phase → branch → PR, and merging is yours. On impl approval, with git.pr: true in tagteam.yaml, tagteam pushes the branch and opens the PR via gh with the phase doc as the body and the phase cost block (#2) at the end. Never merges. Opt-in, because Northstar is production and should keep doing it by hand.

9. Phase from issue

tagteam roadmap add --from-issue 42 writes the roadmap entry and a phase-doc stub from a GitHub issue. Low impact for a solo maintainer; more useful if tagteam ever runs for a team. Park it.

10. Diff-anchored notes · 11. ⌘K palette and shortcuts

Both in the cockpit audit. Small, and they are what make the Diff and Notes tabs worth opening.

12. Health tab: trends across phases

Once #2 records per-phase numbers, a fifth tab: rounds per phase, gate bounce rate, minutes to approve, tokens per phase, review grades (#6), each as a small bar series over the last N phases. This is the view that tells you whether a change to the contract, the model policy or the lenses actually helped. Also the strongest portfolio screenshot tagteam could have: a graph of the loop getting cheaper.

13. Event stream for Aegis

Tagteam's evidence (rounds, gates, verdicts, grades, costs) is in a SQLite file per project. Aegis is your quality control plane. A tagteam events --follow --json firehose (or a JSONL file the watcher appends to, which .tagteam/turns/*.events.jsonl almost is) lets Aegis ingest tagteam without tagteam knowing about Aegis. Cheap, and it makes the two projects one story.

14. Rule from a phone

Escalations wait until you are at the desk. The cockpit binds loopback with a page token; over Tailscale with --host it already works, and the Needs-you card is the only screen a phone needs. What is missing is a phone-width layout for that card and a hard rule that only rule/answer/resume are reachable remotely. Fun, but the security surface has to be designed, not added. Later.

Deliberately not on the list

  • Saloon theme packs (Phase 44). Charming, scheduled, and the cheapest way to lose a week. Keep it after the measurement work.
  • Thin MCP server. The backlog says revisit only if headless proves insufficient for non-Claude agents; nothing since says it has.
  • Auto-merge, scheduler that starts worktrees. The roadmap-DAG phase excluded them on purpose; the reasons still hold.
  • tmux / Windows work. Per your standing note: later.
