Agents & models: where a cheaper model is safe, and where it is not

Your instinct is right, with one correction. Running and monitoring a test suite does not need a frontier model — and tagteam already knows that: the gatekeeper runs the suite with no model at all. The real waste is not "Fable watching pytest". It is frontier-model context growing inside a turn, and rounds that should never have happened. The plan below is: measure first, pull the free levers, then tier the activities that are provably safe to tier.

Verified vs. hypothesis. Everything marked verified was read from the code, the usage table in this repo's .tagteam/tagteam.db, or the current Claude Code docs. Everything marked hypothesis needs the measurement in §6 before anyone builds on it.

1. What tagteam does today verified

No model is hardcoded

Model choice is entirely per-role, static, in tagteam.yaml: agents.<role>.headless.args: ["--model","opus"]. The Claude adapter's allowed-option table already accepts --model, --fallback-model and --effort (tagteam/headless.py:166-168); Codex accepts -m/--model.

The gate is model-free

gatekeeper.py runs the test command, the scope check and the plan-doc check with subprocess. A failing submission bounces before any reviewer tokens are spent. On this repo it runs ~4 min per submission.

Usage is already recorded per turn

The usage table has model, provider, kind, tokens, cache reads/writes, cost and duration for every headless turn, panel lens, brief and chat turn. Nothing groups it by model yet.

No subagents ship

The plugin is one skill and one hook. Nothing tells the lead "delegate the test run to a small model", so a frontier lead reads every line of pytest output into its own context.

Panel lenses inherit the reviewer's model

The scope lens (a diff-vs-plan comparison) runs on the same model and effort as the correctness lens. There is no per-lens, per-kind or per-cycle-type override.

Codex turns are unpriced

tagteam usage shows cost=- for 25 of 25 reviewer turns. Half of every comparison is blind until an estimate exists.

4. What Anthropic's cost guidance says, applied to tagteam

These are the parts of the current cost-optimization guidance that change the plan. They argue against jumping straight to "swap the reviewer to Sonnet".

  • Effort before model. On current models, lower effort on the stronger model often matches a weaker model at high effort, and costs less per completed task. Measured: on long-horizon coding, Opus 5 gave up ~2 points at medium for half the cost, ~8 points at low for a quarter. Research-shaped work is nearly flat: medium matched default accuracy at 70–85% of the cost.
  • Cost per completed task, not per request. A cheaper reviewer that misses a bug costs a whole extra round: a lead turn, a gate run, a reviewer turn and one of the ten rounds' worth of attention. Price the tail.
  • Re-run failures at higher effort. When there is a checker, run at low and re-run failures at the default: same pass rate for ~half the cost in Anthropic's coding runs. Tagteam has a checker for the lead's work (the gate) but not for the reviewer's judgment. See §6 for how to get one.
  • Caches are model-scoped. A cascade forfeits cache reuse across its models. In tagteam each turn is a fresh process, so the cross-turn cache is already cold; what matters is the cache within a turn's agent loop. A subagent starts a fresh prefix with no cache shared with the parent.
  • Orchestrator pays only when there is bulk to hand off. Many independent pieces, or bulky intermediates the parent does not need. A dependent chain that fits one context is cheaper on one model. Test output and codebase search are exactly "bulky intermediates the parent does not need".

6. Proposed plan, in the order the evidence supports

Step 0 — Tomorrow, zero code: try effort and fallback on the reviewer now

The adapter already accepts these. Put them in tagteam.yaml and run one real phase:

agents:
  reviewer:
    name: claude
    headless:
      args: ["--model", "opus", "--effort", "medium", "--fallback-model", "sonnet"]
  lead:
    name: codex
    headless:
      args: ["-m", "<codex model>", "-c", "model_reasoning_effort=medium"]   # confirm flag names with `codex exec --help`

Watch tagteam usage and the round count. This is the "sweep effort before touching the model" step, and it costs nothing to try. Note the Codex effort flag was not verifiable from Anthropic docs; check the Codex CLI's own help. verify

Step 1 — Measure: usage by model and kind, Codex price estimate, phase cost report now

  • tagteam usage --by model and --by kind (the columns exist; only the roll-up is missing).
  • A price table for Codex models so cost is an estimate instead of -. Mark estimates as such.
  • On impl approval, write one line to the phase doc and decision log: rounds, bounces, tokens by role, API-equivalent cost, wall clock. This is portfolio evidence too.
  • Per-model breakdown from modelUsage in the stream-json result, so subagent spend inside a turn shows up under the turn.

Step 2 — Your handoff history is an eval set now

Every past round in docs/handoffs/*_rounds.jsonl across your projects is a labeled example: a submission, a reviewer verdict, and (where it went to you) the arbiter's ruling. That is exactly what the cost guidance says you need before swapping a model and do not usually have.

tagteam bench review --phase X --round N --cell opus:medium --cell sonnet:high --cell haiku:high
# replays the reviewer packet for that round in a scratch worktree at the checked commit,
# runs each cell with the panel contract (verdict.json, no cycle writes),
# and prints: verdict per cell vs. the recorded verdict, blockers found, tokens, seconds

Start with 10 rounds where the reviewer found a real blocker and 10 where it approved. If Sonnet at high effort finds the same blockers, the scope and verification lenses can move. If it does not, you have the number that says why not.

Step 3 — Model policy by activity kind, not just by role after step 2

# tagteam.yaml
models:                      # every entry optional; falls back to agents.<role>.headless.args
  lead.plan:      {effort: high}
  lead.impl:      {effort: xhigh}
  reviewer.review:{effort: medium}
  panel.scope:    {model: sonnet}
  panel.verification: {model: sonnet, effort: high}
  briefer:        {model: sonnet}
  summaries:      {model: haiku}     # digest, round one-liners (03-features)

Implementation is small: the spawn path already builds argv per kind; this merges a per-kind override into the role's validated args. The kind is already recorded in the usage table so the effect is measurable per kind.

Step 4 — Ship a subagent kit in the plugin after step 2

Claude Code subagents support model, effort, tools and disallowedTools in frontmatter, and their usage rolls into the parent's modelUsage. The kit gives the frontier agent a cheap place to put bulky steps:

test-runner haiku

tools: Bash, Read · disallowedTools: Write, Edit. Runs the command it is given, returns counts, failing test ids and the last lines of each failure. Never fixes. Keeps pytest output out of the parent's context; the parent's cache prefix stays stable for the rest of the turn.

explore haiku / sonnet

Read-only fan-out search. Returns pointers, not file dumps. Same shape as Claude Code's built-in Explore, shipped so both roles have it in every project.

codex-brief sonnet

Already exists at user level. Backlog note says: check whether its briefs are what actually gets submitted, or get rewritten. Step 1's data answers that.

verifier sonnet · no write tools

Re-checks a claim in the submission ("12 new tests, all green") without being able to fix anything. Structural read-only via disallowedTools, per your rule that verifiers must not have write tools.

The headless spawn can also set CLAUDE_CODE_SUBAGENT_MODEL in the child's environment, which pins every subagent in that turn to a cheaper model without editing agent files. That is a one-line change and a good first experiment.

Subagents do not reduce the number of tokens the frontier model outputs. They reduce what it reads back, and they keep its context small so each subsequent call in the loop is cheaper. Expect the win on long impl turns with many test runs; expect nothing on a short plan turn.

Step 5 — Lead self-review pre-flight measure rounds/phase first

Before submitting, the lead runs the scope and verification lenses on Sonnet against its own diff and fixes what they flag. A cheap round that never becomes a real round. Measure with the round count per phase from step 1; if rounds do not drop, remove it.

7. What can go wrong

A cheap reviewer approves junk

The failure mode that costs the most and shows up last. Mitigation: only move lenses whose output is checkable or checklist-shaped; keep correctness on the frontier; run the bench in step 2 before and after.

Effort too low on the lead

Lower effort means fewer, more consolidated tool calls and terser output. On a hard impl phase that shows up as more rounds. The round count is the alarm; the per-phase report in step 1 rings it.

Two currencies, one dashboard

Dollar estimates for subscription users are a proxy. Label them "API-equivalent" everywhere; surface the window signal next to them.

Policy sprawl

A per-kind model table is a new config surface. Keep every entry optional, keep the role default as the fallback, and print the resolved policy in tagteam state so what ran is never a mystery.

8. Direct answer to the question you asked

Should activities be broken into subagents on cheaper models? Yes for three specific activities, no as a general policy.

  • Yes: test running inside a turn (Haiku, read-only), codebase search (Haiku/Sonnet), and summaries that do not exist yet (digest, round one-liners: Haiku). All three have checkable or bounded output and bulky intermediates the frontier model does not need.
  • Probably, after the bench: scope lens, verification lens, briefer, submission drafting on Sonnet.
  • No: correctness review, plan and impl authoring, the arbiter chat. Sweep effort on the frontier model there instead; that is the measured cheaper path.
  • Bigger than any of it: fewer rounds and a smaller reviewer packet. A round avoided saves two frontier turns and a gate run.
